## Backend changes
- Current permissions are loaded from SQL once per HTTP request, never persisted in JWT/session or a cross-request cache.
- GET /api/permission/me returns organizationId, roleId, permissionVersion, and menu-keyed view/add/update/delete Boolean grants with Cache-Control: no-store.
- Central action checks cover all existing feature and management APIs, including dynamic Add versus Update endpoints.
- Permission reads/writes and role management are scoped to the caller organization. Rejects stale permission edits, out-of-scope role assignment, privilege escalation, and loss of the last administrator's permission-management access.
- Attachment list/preview/download/delete now enforce organization ownership.
- PUT /api/user/me has a restricted profile contract; role, organization, active status, department, and password cannot be supplied through it.
- JWT identity takes precedence over unrelated browser session UUIDs in organization/user/team/department operations.
- Global menu catalog mutation is denied to organization-level administrators.
- Existing provider abstraction, reply/summary contracts, upload size/text limits, and OAuth routes were preserved.

## Frontend changes
- Added shared in-memory permissions.js bootstrap. Every page waits for access verification before feature initialization.

- Permission editor now displays independent View/Add/Update/Delete checkboxes. Other actions require View; deselecting View clears them. Saves include the revision for conflict detection.
- Profile uses its dedicated restricted endpoint. Corrected existing role-delete request contract mismatch.
